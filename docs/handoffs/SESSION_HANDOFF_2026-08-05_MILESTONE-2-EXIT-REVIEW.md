## 下一刀：SLICE-M2-04

建議名稱：`SLICE-M2-04_B00待辦與身分確認`。

合併理由：B-00 P0 的「等我處理的事項」本來就明列待身分確認；佇列的目的地就是
UNVERIFIABLE 人工確認畫面。拆開會留下只有佇列沒有處理頁，或只有處理頁但找不到工作的
半套流程。此刀只把既有控制接到使用者流程，不新增豁免或弱化 SOD-07。

### 建議納入

- B-00 依目前登入自然人聚合可處理工作：待身分確認、待覆核、待批准、被退回／待補證據、
  未完成草稿。
- 每列固定顯示客戶、法人、期間、狀態，不因版面省略。
- 僅顯示有權且被指派的案件；未指派案件的名稱、計數與彙總都不得洩漏。
- 一鍵回到明確工作物件，而不是只回案件首頁。
- UNVERIFIABLE 確認頁顯示宣告目標、偵測結果、證據強度、批次版本與確認理由。
- 只有資料接受角色可確認；上傳者不得確認自己，角色切換不得繞過。
- 確認建立不可變 Resolution 與 DomainEvent；同一評估不得重複確認。
- 確認後 `identity_status = MANUALLY_RESOLVED`，仍須重新通過 G-01 才能 ACCEPTED。
- API 直接呼叫的越權、跨案件、跨租戶與 SOD 繞過均須拒絕並留痕。

### 明確不納入

- 背景工作技術進度／`/admin/jobs` 替代視圖（B-00 P1）。
- 自動保存、離線同步、`edit_session_id`、Session 恢復（另立阻擋切片）。
- 期間狀態機、多基礎、正式交付、折算。
- DISC-001 的控制弱化或例外政策調整。
