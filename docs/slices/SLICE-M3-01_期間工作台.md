# SLICE-M3-01　B-02 期間工作台

> 狀態：**走查修訂後定稿**（半頁實作契約）。風險由「低」改為**中低**——本刀含一份
> 最小 migration。

## 為什麼是這一刀，而不是折算

基線的 MVP 3 是**折算與對帳**（REQ-FX-001／REQ-CFS-001）。它屬**第一級風險**
（幣別、金額精度、CTA 必須物化不得由兩幣別相減、匯率版本凍結），依既定節奏
需要較完整的事前契約，不適合當「轉向可見產品流程」的第一刀。

而目前有一個**能力完整、入口缺席**的缺口：§25.8 期間狀態機（0022）已是 DB 唯一
裁決點，13 個狀態、角色矩陣、覆核覆蓋評估、fail closed 全部就緒，但使用者只能
用 `POST /period/transition` 打它——**沒有畫面**。里程碑 2 的三刀（映射、調整、
計算）都以批次為入口，「這一期現在能做什麼」目前只存在於資料庫裡。

補上這個入口，整條流程才第一次以**期間**串起來，而且不新增任何控制面。

## 範圍

`GET /b02?revision=…`：一個期間的工作台。

| 區塊 | 內容 |
|---|---|
| 期間狀態 | 目前狀態、`revision_no`、首期旗標、四欄脈絡（客戶／單位／曆別／期間） |
| 下一步 | **只列出目前狀態的合法遷移**，且僅在使用者持有該遷移所需角色時渲染按鈕 |
| 未達成條件 | 遷移被擋的原因（G-02 未映射列數、未批准調整筆數、SoD 未滿足筆數） |
| 尚未實作 | `Gxx_NOT_IMPLEMENTED:` 的遷移**明確標示「守衛尚未實作」**，不得畫成可點 |
| 本期物件 | 批次、調整、計算執行、證據包的計數與一鍵回位 |

**授權（案件層）：完整 B-02 僅 R2／R3／R4。**
§24.6 註③明確限制「R1 僅看得到自身提交狀態，非期間全貌」，而 §28 的 B-02 主要角色
也是 R2／R3／R4。讓 R1 看到期間狀態、阻擋項與全部調整／計算數量會越過該限制。
R1 維持現有 B-00 與上傳入口，只看自己的提交與補件狀態；**本刀不另建 R1 精簡版期間
工作台**（要做是獨立一刀，且需先想清楚「自身提交狀態」的邊界）。

## 唯一的 migration：0028　遷移規格函式

「下一步由 DB 同一份事實推導」目前**做不到**——0022 的合法遷移表與角色矩陣寫在
trigger 的 `CASE`／`IF` 裡，沒有任何可供畫面查詢的介面。若堅持「無 migration」，
工程最後只能在 TypeScript 重寫一次，正好違反本刀最重要的原則。

因此允許一份最小 migration：

```
fn_period_transition_spec(from_status)  唯讀
  → requested_to, required_role, availability, unavailable_code, unavailable_reason
```

- 0022 的 trigger **改為呼叫這個函式**，不再內嵌 CASE／IF。
- B-02 讀**同一個函式**。
- `app_runtime` 只獲 EXECUTE；函式定義的擁有者不是它，改不動。

**這不是新增控制，是把既有控制抽成唯一可查詢來源。** 驗收以既有期間測試
（DB 29 條＋端到端 37 條）證明遷移行為、錯誤碼與事件**完全不變**。

## 不做

- **不新增任何遷移邏輯**：合法遷移表、角色矩陣、聚合守衛的**內容**一字不改，
  只換存放形式。畫面所列的「下一步」必須讀 0028 的函式，不得在 TypeScript 再寫一份。
- **不得自行裁決能否遷移**：阻擋數量可做成讀取模型，但 POST 永遠重新交給 DB 判定。
- 不實作 `REOPENED`、不解除任何 `Gxx_NOT_IMPLEMENTED:`。
- 不做期間建立／刪除 UI（期間目前由種子建立）。
- 不碰折算、匯率、CTA。

## 驗收

1. 期間狀態、首期旗標與四欄脈絡正確顯示。
2. 只渲染**目前狀態的合法遷移**；非法遷移不出現在畫面上。
3. 角色不符者看不到該按鈕；**繞過畫面直接 POST 仍被 DB 擋下並留 CVA**
   （既有 0022 行為，本刀補端到端證明）。
4. `Gxx_NOT_IMPLEMENTED:` 的遷移標示為「守衛尚未實作」，且**不得**被畫成可點。
5. 未達成條件顯示可行動的原因（幾列未映射、幾筆未批准），不是只說「被擋」。
6. **R1、租戶層角色與未指派者：整頁 403**，不洩漏客戶名稱、狀態或計數。
7. 反證：把「下一步」改成列出全部 13 狀態 → 測試轉紅。
8. **0028 重構後遷移行為、錯誤碼與事件完全不變**（既有期間測試全綠，不改斷言）。
9. 完整測試一輪全綠。

## 風險

**中低。** 含一份 migration，但它只搬運既有規則、不新增控制面，也無會計語意變更。
兩個實質風險：
1. **重構 0022 的 trigger 時改變行為**——以既有期間測試為判準，斷言一字不改。
2. **在畫面層重寫一份遷移表**——驗收 2 與 7 專門釘這一點。
