# SLICE-M3-01　B-02 期間工作台

> 狀態：**待走查**（半頁實作契約；依 2026-08-08 的節奏裁定，第二級風險不寫長文件）

## 為什麼是這一刀，而不是折算

基線的 MVP 3 是**折算與對帳**（REQ-FX-001／REQ-CFS-001）。它屬**第一級風險**
（幣別、金額精度、CTA 必須物化不得由兩幣別相減、匯率版本凍結），依既定節奏
需要較完整的事前契約，不適合當「轉向可見產品流程」的第一刀。

而目前有一個**能力完整、入口缺席**的缺口：§25.8 期間狀態機（0022）已是 DB 唯一
裁決點，13 個狀態、角色矩陣、覆核覆蓋評估、fail closed 全部就緒，但使用者只能
用 `POST /period/transition` 打它——**沒有畫面**。里程碑 2 的三刀（映射、調整、
計算）都以批次為入口，「這一期現在能做什麼」目前只存在於資料庫裡。

補上這個入口，整條流程才第一次以**期間**串起來，而且不新增任何控制面。

## 範圍

`GET /b02?revision=…`：一個期間的工作台。

| 區塊 | 內容 |
|---|---|
| 期間狀態 | 目前狀態、`revision_no`、首期旗標、四欄脈絡（客戶／單位／曆別／期間） |
| 下一步 | **只列出目前狀態的合法遷移**，且僅在使用者持有該遷移所需角色時渲染按鈕 |
| 未達成條件 | 遷移被擋的原因（G-02 未映射列數、未批准調整筆數、SoD 未滿足筆數） |
| 尚未實作 | `Gxx_NOT_IMPLEMENTED:` 的遷移**明確標示「守衛尚未實作」**，不得畫成可點 |
| 本期物件 | 批次、調整、計算執行、證據包的計數與一鍵回位 |

授權（案件層，§24.6 期間列）：檢視 R1／R2／R3／R4；發起遷移的角色由 **DB 判定**，
畫面只依 `role_assignment` 決定要不要渲染按鈕。

## 不做

- **不新增任何遷移邏輯**：合法遷移表、角色矩陣、聚合守衛全部留在 0022。
  畫面所列的「下一步」必須由**同一份 DB 事實**推導，不得在 TypeScript 再寫一份。
- 不實作 `REOPENED`、不解除任何 `Gxx_NOT_IMPLEMENTED:`。
- 不做期間建立／刪除 UI（期間目前由種子建立）。
- 不碰折算、匯率、CTA。

## 驗收

1. 期間狀態、首期旗標與四欄脈絡正確顯示。
2. 只渲染**目前狀態的合法遷移**；非法遷移不出現在畫面上。
3. 角色不符者看不到該按鈕；**繞過畫面直接 POST 仍被 DB 擋下並留 CVA**
   （既有 0022 行為，本刀補端到端證明）。
4. `Gxx_NOT_IMPLEMENTED:` 的遷移標示為「守衛尚未實作」，且**不得**被畫成可點。
5. 未達成條件顯示可行動的原因（幾列未映射、幾筆未批准），不是只說「被擋」。
6. 租戶層角色與未指派者：整頁 403，不洩漏客戶名稱或計數。
7. 反證：把「下一步」改成列出全部 13 狀態 → 測試轉紅。
8. 完整測試一輪全綠。

## 風險

低。無新 migration、無新控制面、無會計語意變更。唯一的實質風險是
**在畫面層重寫一份遷移表**——驗收 2 與 7 就是為了釘住這一點。
