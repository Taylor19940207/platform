# 基線凍結硬規則（2026-08-03 起生效）

**沒有程式實作、真實資料或使用者測試證據，不再修改《產品研究與要件手冊》與《基本設計書》。**

新想法一律記入 `docs/BACKLOG.md`，不立刻開 CR。只有下列情況才允許修改基線文件：

1. 阻止 MVP 繼續開發
2. 會造成資料不可逆
3. 涉及資安或法規風險
4. 真實案件證明現行設計錯誤

其他問題在程式碼、issue 或短 ADR（`docs/adr/`）裡處理。

## 文件權威順序（矛盾時依此判斷）

1. 《產品研究與要件手冊 v1.2》——做什麼、P0 範圍、驗收
2. 《基本設計書 v1.1》——資料、流程、模組、畫面怎麼實作
3. CR-001／CR-002——只看決策原因；內容已併入正式文件
4. 稽核報告——只用於發行驗證
5. 歷史版本——不使用

工程上以 Markdown 為準，PDF 只供閱讀。

## 背景

設計文件在 MVP 前置階段已超過一般所需（多基礎、期間組成、版本凍結、跨客戶誤置、
SoD、資料粒度與可重演性都已提前解決——這些有價值）。但文件修訂迴圈開始消耗比
原型驗證更多的時間：一個新問題會同時改動手冊、設計書、CR、稽核器和交付包。
從現在起，證據先於文件。
